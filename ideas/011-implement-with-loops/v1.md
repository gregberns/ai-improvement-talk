# Implement With Loops — Don't Just Fire And Forget

**Category:** `[workflow]`

## Symptoms
Once you're using specs, you'll find they don't always turn out how you'd like. Two distinct problems:

## Problem 1: Agent Doesn't Implement the Spec
The spec was well defined, but parts are missing from the implementation.

**Solution:** Ralph Loop.
- Implement a little
- Check what was implemented against the spec
- Write more
- Check again
- Loop — until the implementation resembles the spec

Contained in oh-my-claudecode. Ask Claude about the "Ralph Loop."

**Background:** Read about the Ralph Loop: https://ghuntley.com/ralph/ — by the guy who coined the name. The concept goes by different names (e.g., "attractor" pattern) but it's the same idea.

## Problem 2: Spec Has Inconsistencies
The implementation followed the spec... but the spec itself had gaps or contradictions. The code is "correct" but wrong.

**Solution:** Multi-agent spec review before implementation.

3 agents reviewing from different angles:
- **spec → plan** (forward coverage): does the plan cover everything in the spec?
- **plan → spec** (reverse traceability): does every plan item trace back to a spec requirement?
- **plan → context** (codebase alignment): does the plan make sense given the actual codebase?

See: [Xexr gt-toolkit Stage 6: Plan Review](https://github.com/Xexr/gt-toolkit/blob/main/formulas/README.md#stage-6-plan-review)
