# Write Specs — Become The Architect

**Category:** `[workflow]`

## Symptom
"I tell Claude in detail what I want, it goes and does it, and I really don't like the results."

## Root Cause
No spec. You're describing what you want verbally, the model interprets it, and the interpretation doesn't match your vision. There's no shared document to align on before implementation begins.

## The Pitch
"But that's boring — I don't like writing all that!"

Don't write it all. Brain dump, then iterate with Claude. You're the Architect. Claude helps you think through the details.

## Action
Start simple:
1. Write a single spec file
2. Clear your session
3. Implement from the spec
4. You should see improvement immediately

Key: **Disable Claude Plan Mode** (ask Claude how). You need to actively iterate on the spec, not let Claude plan in its head. Write to disk, iterate on the written artifact, THEN implement.

## Warning
If you do this, you may see more success from this than any other single step. (Caveat: to make it really good, you need the Ralph Loop — idea 011.)

## Why Specs Work
- Force deep thinking about HOW code will be written
- Force research into the problem space
- Code snippets in specs enforce coding conventions
- If the code samples in your spec don't follow convention — ask what's missing from project metadata? (Feedback loop to idea 005/006)

## The Full Spec Process (Advanced)
1. **Problem Space** (Brain Dump)
2. **Decompose & Requirements** (high and low level ideas)
3. **Research** (Claude researches your ideas)
4. **Nit Pick the Details Loop** (take a section at a time and interrogate it)
5. **SPEC!** (Claude formalizes into a doc)
6. **Implement** (using a Ralph Loop — idea 011)
7. **Code Review** (architect, critic, QA agents from oh-my-claudecode)
8. **Spec Review** (architects validate the spec itself)

## Engineer Quote (Illustrative — the other extreme)
Eng #1:
> "I do not write any of my code, but I micromanage the shit out of claude."
> "I do not use any skills, built-in planner, mcps or any other fancy features."
> "I have a living document PLAN.md with a checklist for everything I do."
> "I find my approach maximizes the code quality and familiarity and minimizes tokens used, but sacrifices everything else."

This engineer has discovered the value of written plans (PLAN.md) but is manually micromanaging instead of letting the spec + loop do the work. There's a middle ground.
