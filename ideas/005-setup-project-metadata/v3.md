# Set Up Your Project Metadata

**Category:** `[metadata]`

## 1. Symptom

"It's not following my project's conventions! Every time it's missing things!"

You're yelling at the agent because it didn't follow your conventions again. Or: you've picked a tool (003/004), you're invested, but you're running it with zero configuration and wondering why results are inconsistent.

## 2. What to Change

You need to configure your agent for your project. In code you put guardrails on your programs — WHY NOT YOUR CODING AGENTS?

Start a new session:

> I need you to set up this project so coding agents can work effectively with it. Research best practices for agent configuration, then explore the project — understand the conventions, patterns, and structure across different areas. Identify where an agent would lack context or get confused. Ask me about any conventions or workflows I care about that you can't infer from the code. Create AGENTS.md files where needed, with CLAUDE.md symlinked to them. Use sub-agents to research different areas of the project.

The agent does the heavy lifting. You review what it generates, ask questions, provide context about conventions it can't see in the code.

## 3. Reinforcing Patterns

- Root AGENTS/CLAUDE should be 100-150 lines max. Subdirectories get their own files.
- Run the agent on different areas of the codebase — it should discover the project, not just be told about it.
- Review what it generates. Ask questions. Understand what it created and why.

## 4. Why What You Were Doing Wasn't Working

The agent starts every session with no knowledge of your project beyond what it can read in the moment. Without metadata files, it rediscovers your conventions every time — reading code, guessing patterns, often guessing wrong. Every inconsistency in its output traces back to missing context.

## 5. Why the Alternative Works Better

Context gets auto-injected when the agent enters relevant areas. It knows your patterns before writing code. Consistency across sessions improves because the knowledge is persistent — on disk, not in a conversation that gets cleared.

## Hidden Arc Note

This is the first time the dev is defining expectations for the agent in writing. Baby step toward spec-driven — they don't know it yet.

The action itself — "tell the agent the problem, let it research and figure out the approach" — demonstrates the collaborative pattern. They're not dictating file contents. They're describing a problem. This is the mode we want them in for everything that follows.

## Brownfield / Convention Conflicts

For projects with old AND new patterns: needs explicit metadata. "Old pattern X exists in /legacy. All new code uses pattern Y. Never use X in new code."

Might be a sub-article or section — "specific conventions aren't being followed" is a different symptom from "no conventions configured at all."

## Deliverable: The Prompt

Need to build and test a solid prompt for this first-pass setup. Key constraints:
- Research project areas (use sub-agents)
- Build a plan before implementing
- Ask user about key conventions
- Create AGENTS files (CLAUDE symlinks)
- NO commands, hooks, or advanced features
- Generic across tools if possible

## Open Questions

- AGENTS/CLAUDE symlink convention — prescribe or let agent decide?
- Library-specific patterns — how detailed?
