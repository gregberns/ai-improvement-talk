# Set Up Your Project Metadata

**Category:** `[metadata]`

## Symptom
"It's not following my project's conventions! Every time it's missing things! What is the problem!"

You're yelling at the agent because it didn't follow your conventions again.

## Root Cause
Claude's context isn't getting loaded with critical information about your conventions. It doesn't know what you know. It doesn't have your team's patterns in its context window.

## The Key Insight
In code you put guardrails on your programs — WHY NOT YOUR CODING AGENTS?

## What "Project Metadata" Means
All the encoded patterns and practices embedded in the project through:
- CLAUDE.md / AGENTS.md files (root and nested)
- Rules
- Hooks
- Commands
- .claude configuration

Root AGENTS/CLAUDE should be 100-150 lines. No more. You can have additional files in subdirectories for specific areas.

## Action
Start a new Claude session. Tell it:

> "I need you to do extensive research into how to best set up this large project to work well so Claude Code can work effectively and follow its conventions."

Tell it what you're struggling with! Review what it generates. Ask questions:
- "What is a command?"
- "Why are there CLAUDE files several folders deep?"
- "What are hooks for?"

Use this process to have Claude teach you about the tools and what they're for.

## Expected Results
- Context gets auto-injected when Claude enters relevant areas
- Generally better performance
- Consistency across sessions should improve

## Open Questions
- Do we give a brief overview of what each piece (hooks, commands, rules, CLAUDE.md, AGENTS.md) is for?
- Or do we just tell them to ask Claude? (The "have Claude teach you" approach worked in the talk)
- Example project metadata to show? Or is that too prescriptive?
