# Evolve Your Project Metadata

**Category:** `[metadata]`

## 1. Symptom

You set up your project metadata (005). Things improved. But you're still hitting inconsistencies. Some sessions are great, some aren't. The agent follows conventions in one area but not another. It feels better but not reliable.

Or: you've been using the tool for a while, configured some things, but never systematically improved them.

## 2. What to Change

You're an engineer. You've spent years tuning your terminal, your IDE, your shell config, your git aliases. You configure the environment you work in. This agent is now part of that environment. Treat it like one.

You just spent a little time to implement the initial setup (005). Now spend just a little more to tune it in. One focused day. That's it.

**The process:** After each task (around 50-75% of context), before you move on, run this prompt:

> Look back at this conversation. Identify where you lacked context or got confused, where you didn't follow project conventions, and where I could have communicated more effectively. For each issue, think about what metadata improvement — to AGENTS files, rules, or other configuration — would prevent it next session. Generalize the improvements — don't overfit to this specific conversation. Make the changes.

Spend 10 minutes per hour of coding. For 1 day.

## 3. Reinforcing Patterns

- **Generalize, don't overfit.** The agent tends to take your exact words and parrot them back. Push for general principles. "Always use the repository pattern for data access" not "in the last task we needed to use UserRepository."
- **Build abstractions** from specific learnings. One session's problem is often a pattern you'll hit again.
- **The feedback goes both ways.** The prompt should identify where YOU could improve your interaction, not just where the agent needs better metadata. You're tuning the whole system — agent config AND your own habits.

## 4. Why What You Were Doing Wasn't Working

You configured it once and hoped it would be enough. But your codebase evolves. Your conventions evolve. The agent encounters areas of the code that the initial setup didn't cover. Without systematic feedback, the gaps persist session after session.

It's like configuring your linter once and never updating the rules as the codebase grows. The tool is only as good as the configuration you maintain.

## 5. Why the Alternative Works Better

Every session produces signal — what worked, what didn't, where the agent was confused, where you were frustrated. That signal is free intelligence about how to improve. Ignoring it means making the same mistakes next session.

10 minutes of analysis after a session can save an hour of fighting the same issues next time. And the improvements compound — each session gets slightly better.

## Hidden Arc Note

006 is the meta-skill. Everything else teaches a specific behavior. This teaches: analyze, generalize, encode, improve. It's the engine that makes everything else get better over time.

The exercise pattern (create a thing, use it, refine it, use it again) could recur across multiple articles. It's a powerful teaching tool — the dev learns by doing the refinement loop, not by reading about it.

Also: the "feedback goes both ways" idea is important. Most articles about AI tools only talk about configuring the tool. This one says: you're part of the system too. Your interaction patterns matter. The agent's analysis can tell you where YOU need to improve.
