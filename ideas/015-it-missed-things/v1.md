# It Built It But Missed a Bunch of Stuff

**Category:** `[workflow]`

## 1. Symptom

The agent says it's done. You check the work. Stuff is missing. Requirements skipped. Edge cases ignored. It implemented 70% and called it complete.

## 2. What to Change

Have the agent review its own work against the plan (from article 014).

After implementation, before you accept it:

> "Look at what you built. Compare it against the plan we wrote. What's missing? What doesn't match? What did you skip?"

If you saved the plan to a file, point the agent at it. Make it do the comparison systematically — section by section.

## 3. Reinforcing Patterns

- Make this a habit: implementation isn't done until the agent has self-reviewed against the plan
- If it missed things, ask WHY. Was the plan unclear? Was it a context issue? That feedback improves the next plan.
- For larger features: review incrementally, not all at the end. Build a piece, check against plan, build the next piece.

## 4. Why What You Were Doing Wasn't Working

The agent doesn't have persistent memory of what it was supposed to build unless it's written down. In a long implementation, early instructions get pushed out of active context. It's not being lazy — it's losing track. Without a written reference to check against, "done" means "I ran out of things I can remember to do."

## 5. Why the Alternative Works Better

A written plan is a checklist the agent can verify against. Self-review catches gaps before you have to find them. And the incremental pattern (build a piece, check, build the next) means nothing drifts too far before correction.

This is planting the seed for the Ralph Loop — implement a little, check against the plan, implement more, check. We don't name it yet.

## Hidden Arc Note

The user is now doing: plan → implement → review against plan. That's the core loop of spec-driven development. The Ralph Loop. They just don't have the vocabulary yet.

The incremental review pattern (build a piece, check, build the next) is literally the Ralph Loop. When we formally introduce it later (011), it'll feel like naming something they already do.
